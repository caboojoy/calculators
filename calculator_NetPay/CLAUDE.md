# CLAUDE.md — 네트제(세후보장) 급여 계산기

## 프로젝트 개요

**네트제 계산기**: 근로자가 받기로 한 **세후 실수령액(Net)**을 입력하면, 회사가 지급해야 할 **세전 급여(Gross)**를 역산(Gross-up)하고, 회사가 실제로 부담하는 **총 인건비**까지 보여주는 웹 계산기.

- 소속: `caboojoy-calculators` 레포 (allcalcu.com) 계산기 컬렉션의 하나
- 대상 사용자: 중소기업 대표, 경리·회계 담당자, 노무 실무자
- 핵심 가치: 실무 회계 경력 기반의 **정확한 공제 로직**. 근사값이 아니라 실제 급여명세서와 원 단위까지 맞아야 한다.

## 기술 스택 & 구조 (기존 규칙 그대로 따를 것)

- 순수 HTML / CSS / JavaScript — **프레임워크·빌드 도구 금지**
- 계산기 1개 = 파일 3개: `index.html`, `style.css`, `script.js`
- 폴더: `net-salary/` (레포 루트 아래, 기존 계산기 폴더 구조와 동일하게)

- 차트 필요 시 Chart.js (CDN)
- 폰트: Noto Sans KR / Noto Serif KR(한글), IBM Plex Mono(숫자)

## 계산 로직

### 1. 정방향 (Gross → Net) — 모든 계산의 기준 함수
```
과세급여 = 세전급여 − 비과세(식대 등)
국민연금 = clamp(과세급여, 하한, 상한) × 근로자요율 → 원 단위 절사
건강보험 = clamp(과세급여, 하한, 상한) × 근로자요율 → 원 단위 절사
장기요양 = 건강보험료 × 장기요양요율(건보료 대비) → 원 단위 절사
고용보험 = 과세급여 × 0.9% → 원 단위 절사
소득세   = 근로소득 간이세액표(과세급여, 공제대상가족수, 8~20세 자녀수) × 선택비율(80/100/120%)
지방소득세 = 소득세 × 10% → 10원 미만 절사
실수령액 = 세전급여 − (4대보험 근로자분 + 소득세 + 지방소득세)
```
- 절사 규칙(원 단위 / 10원 단위)은 **기존 4대보험·소득세 계산기 구현과 반드시 일치**시킬 것. 다르면 먼저 보고.

### 2. 역방향 (Net → Gross) — 네트제의 핵심
- 간이세액표가 구간 테이블이라 **대수적 역함수가 없다** → **이분탐색(binary search)** 으로 구현
- 탐색 범위: `low = 목표Net`, `high = 목표Net × 2` (부족하면 확장)
- 원 단위 정수로 탐색. 조건: `forward(gross).net >= 목표Net` 을 만족하는 **최소 gross**
- 간이세액표 구간 경계에서 net이 단조 증가하지 않는 지점이 있을 수 있음 → 결과 gross에서 `forward()`로 재검증하고, 목표 대비 차액(예: +3원)을 화면에 표시
- 지급 단위 반올림 옵션: 원 / 10원 / 100원 / 1,000원 단위 올림

### 3. 회사 부담 총 인건비
```
총 인건비 = 세전급여 + 국민연금(회사) + 건강보험(회사) + 장기요양(회사)
          + 고용보험(회사: 실업급여 0.9% + 고용안정·직능 0.25~0.85%) + 산재보험(업종별)
```
- 고용안정·직능 요율은 기업 규모 선택(150인 미만 0.25% 등), 산재 요율은 직접 입력(기본값 제공)

### 4. 연간 환산 & 연말정산 리스크 안내
- 월 결과 × 12 연간 요약
- 네트제의 실무 쟁점 안내문 표시: 연말정산 추가납부/환급분을 누가 부담하는지 계약서에 명시 필요, 회사가 대신 낸 세금은 다시 근로소득으로 과세될 수 있음 (계산에 반영하지 않고 **안내 문구로만**)

## 요율 설정 (연도별 config 분리 필수)

모든 요율·상하한·세액표는 `script.js` 상단의 **연도별 config 객체**에만 둔다. 로직 코드 안에 숫자 하드코딩 금지.

```js
const POLICY_UPDATED = '2026-10-21'; // 요율 마지막 검증일 — 매년 1월·7월 재확인

const RATE_CONFIG = {
  2026: {
    nationalPension: {
      employeeRate: 0.0475,                         // 총 9.5%
      // 상하한은 7월 기준으로 바뀜 → 기간별로 보관
      bands: [
        { from: '2026-01-01', to: '2026-06-30', min: 400000, max: 6370000 },
        { from: '2026-07-01', to: '2027-06-30', min: 410000, max: 6590000 },
      ],
    },
    healthInsurance: {
      employeeRate: 0.03595,                        // 총 7.19%
      // TODO: 2026 보수월액 상·하한 공식 고시값 확인 후 입력
    },
    longTermCare: {
      rateOfHealth: 0.1314,                         // TODO: 건보공단 고시 원문으로 재확인 (자료마다 12.95%/13.14% 혼재)
    },
    employment: {
      employeeRate: 0.009,
      employerExtra: { under150: 0.0025, priority: 0.0045, over1000: 0.0065, gov: 0.0085 },
    },
    nonTaxable: { meal: 200000 },
  },
};
```
- 사용자에게 "적용 기준 시점(연·월)"을 선택하게 해서 국민연금 상하한 기간을 고르도록 할 것
- `TODO` 표시된 값은 **추측으로 채우지 말 것**. 국세청·국민연금공단·건강보험공단 고시 원문을 확인해서 출처 URL을 주석으로 남기거나, 나(도겸)에게 확인 요청

### 근로소득 간이세액표
- 별도 파일 `taxTable2026.js`로 분리 (데이터만, 로직 없음)
- 국세청 최신 간이세액표 기준. 월급 1,000만원 초과 구간은 세액표의 산식 규칙대로 구현
- 기존 소득세 계산기에 세액표가 이미 있으면 **새로 만들지 말고 재사용** 가능 여부부터 확인

## 금융 계산 주의사항 (과거에 실제로 겪은 버그)

- **부동소수점**: `3,000,000 × 0.009`가 `26,999`로 나오는 문제 → 곱셈 결과에 `.toFixed(2)` 정규화 후 `Math.floor`
  ```js
  const floorWon = (v) => Math.floor(Number(v.toFixed(2)));
  ```
- `!== null` 같은 항상 참인 조건, 중복 HTML ID, 죽은 코드 주의
- CSV 다운로드 기능을 넣는다면 Safari/Firefox 호환 확인

## 화면 구성

1. **입력 영역**: 목표 세후 월급 / 비과세 식대 / 공제대상 가족 수(본인 포함) / 8~20세 자녀 수 / 소득세 비율(80·100·120%) / 적용 시점 / 회사 규모 / 산재 요율 / 지급 단위 반올림
2. **결과 카드**: 필요한 세전 급여(크게) → 공제 내역 표 → 실수령 검증값 → 회사 총 인건비
3. **비교 표**: 근로자 부담 vs 회사 부담 항목별
4. 선택: 세전·공제·실수령 구성 도넛 차트(Chart.js)
5. 하단: 계산 기준 요율·시점 표시, 면책 문구("참고용, 실제 급여는 공단 고지액 기준"), Google Forms 문의 링크

## 테스트 (계산 로직 변경 시마다 실행)

- `tests.html`(또는 콘솔 실행 스크립트)에 검증 케이스 유지
- **왕복 테스트**: 여러 Net 값(200만, 250만, 300만, 500만, 700만, 1,200만)에 대해 `forward(reverse(net)).net >= net` 이고 차이가 최소인지
- **경계 테스트**: 국민연금 상한 근처(659만 전후), 하한 미만, 간이세액표 구간 경계, 비과세가 급여보다 큰 경우, 0·음수·빈 입력
- 정방향 결과를 **기존 4대보험·소득세 계산기 결과와 교차 검증**
- 가능하면 실제 급여명세서 숫자 1~2건으로 원 단위 일치 확인 (내가 제공)

## 작업 방식

- **검토 → 계획 → 구현** 순서. 큰 변경 전에는 무엇을 바꿀지 먼저 요약하고 확인받기
- 한 번에 전부 만들지 말고 단계별로: ① 정방향 함수 + 테스트 → ② 역산 이분탐색 → ③ UI → ④ 회사 부담·연간 → ⑤ 인덱스 등록·SEO
- 기존 계산기 코드를 수정해야 하면 먼저 알릴 것 (다른 계산기에 영향)
- 법령·요율이 불확실하면 지어내지 말고 "확인 필요"로 남길 것
- 커밋 메시지는 한국어, 형식: `feat(net-salary): 역산 이분탐색 구현`
- 응답·주석은 한국어로
